# Systematic Implementation Plan
> Execute inline using executing-plans; user delegated decisions and opted out of design questions.

**Goal:** A locally running, automatically scanning, traceable ML crypto risk detector.
**Architecture:** Deep market-observation, scoring and experiment modules. SQLite owns durable job and scan state; C++ and Python adapters share model parameters and feature definitions.
**Tech Stack:** FastAPI, NumPy, SQLite, C++17, existing Next.js/React UI.
**Spec:** ../specs/2026-11-02-detector-design.md

## Global constraints
Preserve UI structure. UI :3000, API :8000. Five-minute observations; 15-minute target. Never represent missing/stale data or synthetic results as live evidence.

## Review focus
- Failed providers must preserve visible failure and make stale prices unavailable.
- Training/validation/test windows must not overlap across chronological splits.
- Restart must retain experiments and recover queued/interrupted work.
- Native and Python prediction parity, including flat data and invalid prices.
- Replay must score actual dataset rows and produce identical results independent of worker count.

## Decisions
Working copy in outputs/systematic preserves uncommitted original edits. Existing dependency installations may be reused locally; setup script supports a fresh install. Experimental weak-label forecasting is not validated manipulation detection. Benchmark is feature-window replay, not an exchange matching-engine backtest.

## Verification ledger
- 16 backend/native/API tests pass, including four independent-review regressions.
- Next.js production build passes with TypeScript validation enabled.
- Final recorded dataset: 15,856 real windows, all with dated headline coverage. Final sweep: 32 runs plus identical-artifact rerun.
- Final native benchmark: 378.527ms single versus 168.154ms four workers; matching checksums. The initial hoistable benchmark is marked invalid in the ledger.
- Decision: use a separate working copy to preserve uncommitted original changes; startup currently reuses installed dependencies via symlinks. Moving the original requires fresh setup.
- Decision: keep weak-label model available for research, visibly disclose below-baseline quality; not suitable for reliable alerts.
- Decision: use explicit 127.0.0.1 links because a separate old frontend is bound on IPv6 localhost.
- Review fixes: absolute label direction; zero weights for constant features; loaded-source/native identity checks; provider payload errors marked failed.
